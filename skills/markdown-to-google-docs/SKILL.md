# Markdown to Google Docs (Windows / PowerShell 5.1)

Turning markdown into a *natively formatted* Google Doc means driving the Docs API
`batchUpdate` yourself: insert text, then apply `updateParagraphStyle` /
`updateTextStyle` / `createParagraphBullets` over recorded index ranges. Every
hard part below is a Windows or Docs-API trap that silently produces a
plausible-looking but wrong document.

**Working implementation ships with this skill - run it, don't rewrite it.**
Paths are relative to this skill's directory:

- `scripts\Build-GoogleDoc.ps1` - the converter.
  `-Md <file>` (required), `-Urls <urls.json>`, `-Title <text>` (defaults to the
  first `# ` heading), `-OutIdFile <file>` (writes the new documentId).
- `scripts\Verify-GoogleDoc.ps1` - assertion harness.
  `-DocId` (required), `-ExpectTables`, `-ExpectImages`, `-MinH1`, `-MinH2`, `-ExpectUnicode`.
- `scripts\Inspect-Doc.ps1 -DocId <id>` - read-only structure dump: tables, images,
  headings, per-table header row. Free of write quota; use it to look before you rebuild.
- `scripts\New-KrokiUrl.ps1 <*.dot> -OutJson urls.json` - Graphviz -> Kroki URLs,
  fetch-tested and aspect-gated.
- `scripts\GwsClient.ps1` - shared transport; dot-sourced by the others, not run directly.

**Setup:** `npm install -g @googleworkspace/cli` and authenticate (`gws auth login`);
PowerShell 5.1 or later; network access for Kroki. The scripts locate node and
`run.js` from the `gws` shim on `PATH`, falling back to `npm root -g`. Override with
`$env:GWS_NODE_EXE` and `$env:GWS_RUN_JS` (set both) for a non-standard install.

For plain reads/appends use the auto-generated `gws-docs` / `gws-docs-write`
skills instead. Those files are regenerated by `gws generate-skills` - never edit them.

## Symptoms -> cause

| Symptom | Cause | Fix |
|---|---|---|
| `'\|' was unexpected at this time` | routed `--json` through `cmd /c`; cmd eats `\| & < > ^` in ASCII art and `->` arrows | call `node.exe run.js` via `ProcessStartInfo` |
| JSON rejected / quotes vanish | PowerShell 5.1 native-arg quoting mangles embedded `"` and splits on spaces | same - manual `CommandLineToArgvW` escaping |
| Table cells interleaved garbage (`LayeCitationr`) | `Sort-Object index` on hashtables sorts as **strings** (9 > 14) | `Sort-Object { $_.index } -Descending` |
| Published doc has no text, build "succeeded" | function reassigned an unqualified `$sb`, creating a local; buffer stayed empty | `$script:`-qualify all shared accumulator state |
| Mojibake where arrows/em-dashes should be | `Get-Content -Raw` reads UTF-8-without-BOM as ANSI | `[System.IO.File]::ReadAllText($p,[Text.Encoding]::UTF8)` |
| Mojibake only when *reading back* the doc | stdout decoded as ANSI | `$psi.StandardOutputEncoding = [Text.Encoding]::UTF8` |
| Literal `*asterisks*` in output | italics never implemented; or `*` checked before `**` so bold split into two italics | implement `*italic*`, match `**` **first** |
| `oneof field 'cells' is already set` | `updateTableCellStyle` given both `tableRange` and `tableStartLocation` | supply exactly one |
| Extra column, every cell shifted | row split on `\|` inside a backtick span (e.g. a cell containing `` `kg\|kilo` ``) | split only outside code spans, honour escaped pipes |
| Wrapped bullet becomes bullet + stray paragraph | continuation lines not absorbed | absorb until blank/structural line, `Trim()` before join |
| Diagram unreadable, labels ~2.6 pt | wide aspect (e.g. 2669x306) scaled into fixed 468 PT width | keep aspect under ~2.5:1 |
| `Quota exceeded` mid-build | ~60 writes/min/user | pace ~1.1 s/write + exponential backoff |
| `403 accessNotConfigured` hosting images | Drive API disabled on the GCP project | host via Kroki GET URLs (below) |
| `gws CLI not found` from a script | node/gws not on `PATH`, or a non-standard npm prefix | install `@googleworkspace/cli` globally, or set `GWS_NODE_EXE` + `GWS_RUN_JS` |
| Output file written, but not where you expected | `[System.IO.File]::WriteAllText` resolves a relative path against .NET's CWD, not `$PWD` | make it absolute first (below) |
| Doc reads as 1 element, 0 tables, 1 image | `docs` subcommand omitted; gws returned `{"error":...}` and nothing threw | `Invoke-GwsRaw @('docs','documents','get',...)` |

## Transport: never shell out to gws

`gws` is a node shim (`gws.ps1` -> `node run.js`). Both PowerShell 5.1 native-arg
passing **and** `cmd /c` corrupt a JSON body. Invoke node directly and build the
command line yourself. .NET Framework 4.x (PS 5.1) has no
`ProcessStartInfo.ArgumentList`, hence manual `CommandLineToArgvW` escaping:
quote the arg, escape `"` as `\"`, double any backslashes preceding a quote.

The same trap bites sideways while *testing*: a nested
`powershell -NoProfile -Command "..."` whose body contains quotes loses them the
same way, and the child parses the fragments as separate commands. Use `-File` or
`-EncodedCommand` for anything non-trivial.

`scripts\GwsClient.ps1` implements this - dot-source it, never re-derive it:

```powershell
. "$PSScriptRoot\GwsClient.ps1"
$doc = Invoke-GwsRaw @('docs','documents','get','--params','{"documentId":"..."}')
```

Two settings in there are load-bearing:

- `$psi.StandardOutputEncoding = [System.Text.Encoding]::UTF8` - without it every
  Unicode character read back from the API arrives as mojibake.
- Empty or non-JSON stdout throws - a swallowed CLI error otherwise looks like success.

It never hardcodes an install path: `$env:GWS_NODE_EXE`/`$env:GWS_RUN_JS` first, then the
`gws` shim's own directory (`<dir>\node_modules\@googleworkspace\cli\run.js`, with
`<dir>\node.exe` if present), then `npm root -g`.

The subcommand matters: `Invoke-GwsRaw @('documents','get',...)` without the leading
`docs` returns `{"error":...}` as *valid JSON*, so nothing throws - `$d.body.content`
is `$null` and `@($null).Count` is 1, which reads as a one-element document. Callers
that care must check `.error` themselves; the transport deliberately does not throw on
it, because `Build-GoogleDoc.ps1` inspects `.error` to drive its quota backoff.

### The 32767-char command line is a real constraint

`--json` does **not** accept `@file` or stdin (`--json -`). The body goes on the
command line, so the Windows limit applies. Budget ~28000 chars and:

- chunk large `insertText` payloads, advancing the insertion index by each slice's length;
- split large request arrays into several `batchUpdate` calls - only safe for
  requests that do not shift each other's indices (styling). Index-shifting
  inserts must be ordered by the caller.

Incidental: the `gws docs +write` helper rejects `--text <value>` when the value
starts with `-`; use `--text=<value>`.

## Encoding

```powershell
$raw = [System.IO.File]::ReadAllText($path, [System.Text.Encoding]::UTF8)
[System.IO.File]::WriteAllText($out, $text, (New-Object System.Text.UTF8Encoding($false)))  # no BOM
```

Both resolve the path **themselves**, and .NET's working directory is not
PowerShell's - a relative path silently lands somewhere else. Root it first:

```powershell
if (-not [System.IO.Path]::IsPathRooted($p)){ $p = Join-Path (Get-Location).Path $p }
```

Then assert after publishing: the doc text contains the expected codepoints
(U+2192, U+00D7, U+2014) and contains no mojibake pair - a `[char]0x00C3` or
`[char]0x00E2` followed by another char above 0x7F.

## Docs API

**Tables.** `insertTable`, then **read the document back** to get each cell's
first-paragraph `startIndex`. Insert all cell text in **one** batch ordered
**high index -> low index** (requests apply sequentially, so higher inserts
don't invalidate lower indices). One batch per cell burns the write quota.

```powershell
foreach($it in ($items | Sort-Object { $_.index } -Descending)){   # NUMERIC sort - not `Sort-Object index`
  $cellInserts += @{ insertText = @{ location=@{ index=$it.index }; text=$it.text } }
}
```

Re-read again afterwards to compute styling ranges (indices shifted).

**Header shading.** `updateTableCellStyle` is a oneof: pass `tableRange` **or**
`tableStartLocation`, never both, or the whole batch fails.

**Quota.** ~60 writes/min/user. Sleep ~1100 ms after each write; on
`Quota exceeded` back off 20s, 40s, 60s... A long doc dies mid-build otherwise.

**Images.** `insertInlineImage` needs a **publicly fetchable URL** - Google
fetches it server-side; it cannot take bytes.

**Rebuild in place with `-DocId`.** `documents.create` always makes a *new*
document, so omitting `-DocId` changes the URL and orphans anything already
linking to it. To keep the URL - and any edits collaborators made around your
content - pass the existing id:

```powershell
.\scripts\Build-GoogleDoc.ps1 -Md .\content.md -DocId <existing-id>
```

The script **wipes the whole body** (`deleteContentRange` 1..endIndex) and
rebuilds it, so the URL and sharing settings survive but the previous content
does not - any manual edits in that doc are destroyed. Warn the user before
rebuilding a doc they have touched. Only reach for a fresh `create` when you
actually want a second document. If doc A links to doc B, build B first so you
have B's id to reference.

## Diagrams without Drive

Drive API disabled (403 `accessNotConfigured`) and `insertInlineImage` still
demands a public URL -> render Graphviz through Kroki GET URLs. Encoding is
base64url(zlib(source)): `0x78 0x9C` header + raw DEFLATE + big-endian Adler-32.

`scripts\New-KrokiUrl.ps1` does all three steps - encode, fetch-test, aspect-gate:

```powershell
.\scripts\New-KrokiUrl.ps1 .\diagrams\*.dot -OutJson .\diagrams\urls.json
```

It requires HTTP 200 + an `image/*` content type (a 400/404 means invalid Graphviz),
reads the real PNG dimensions (big-endian width at byte 16, height at 20) and exits 1
when the aspect ratio exceeds 2.5:1 (`-MaxAspect` to change it). That gate matters
because the builder inserts at a fixed 468 PT width: a 2669x306 (8.7:1) diagram renders
its 11 pt labels at about 2.6 pt. `rankdir=TB` plus `constraint=false` on cross-cluster
edges is the usual fix. The `-OutJson` map is keyed by file base name, which is what
`[[DIAGRAM:key]]` resolves against.

## Converter correctness

- **`$script:` everything shared.** A function that reassigns an unqualified
  `$sb` creates a local; the build reports success and publishes an empty doc.
- **Inline parsing order:** backtick code, then `**bold**`, then `*italic*`.
- **Table rows:** split on `|` only outside backtick spans; honour `\|`.
- **Bullets:** absorb hard-wrapped continuation lines into the bullet; trim
  before joining or you get doubled spaces.
- **Fenced blocks stay byte-exact** - ASCII art depends on it.
- **Diagrams:** a line containing only `[[DIAGRAM:key]]` becomes an inline image;
  `key` is looked up in the `-Urls` map. No map, no `-Urls` - the block is skipped.

## Verification discipline

Assert structure from the API, not from the build log: heading counts, table
count, per-table header row (shaded + bold + no empty cell), image count with
non-empty `contentUri`, Unicode integrity. Then **prove the harness can fail** -
run it once with a deliberately wrong expectation and confirm a non-zero exit -
before trusting a PASS.

```powershell
.\scripts\Verify-GoogleDoc.ps1 -DocId $id -ExpectTables 6 -ExpectImages 3 -MinH1 8 -MinH2 10
.\scripts\Verify-GoogleDoc.ps1 -DocId $id -ExpectTables 999    # must exit 1
```

Unsupplied expectations print `SKIP:`. The Unicode-presence assert is opt-in
(`-ExpectUnicode`) since not every document contains arrows or em-dashes; the mojibake
scan always runs.

Read the exit code from `powershell -NoProfile -File .\scripts\Verify-GoogleDoc.ps1 ...`.
`$LASTEXITCODE` after `&` does not reliably carry a script's own `exit`, so the
deliberately-wrong run can look like it passed - which defeats the whole point of it.
